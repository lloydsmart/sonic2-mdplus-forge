# Sonic 2 MD+ Forge v3.0.0

Release date: 2026-10-03.

Version 3.0.0 freezes the validated Production and curated Bugfixed build
flavours before further Bugfixed polishing. Production remains the default,
byte-identical to its hardware-qualified Stage 5 image. Bugfixed integrates the
frozen curated gameplay policy with Forge MD+ in isolated outputs and has its
own strict identity and layout profile.

This release contains tooling, configuration and documentation only. It does
not distribute Sonic 2 ROMs, Sega game assets, upstream source/assets, Addryu
audio, converted soundtrack files, disc images or generated MiSTer packages.
Users supply their own lawfully obtained soundtrack files for local builds.

## Why a major release

Version 2.0.0 exposed the previous implementation through public `--legacy`
options and `*-legacy` Make targets. Current development removes that
implementation and those interfaces. The tooling follows Semantic Versioning,
so this breaking interface change requires v3.0.0 rather than v2.1.0.

The `msu-md-sonic2` source path, separate ASL build, legacy-only options,
converter, ASM helpers, verifier and exclusive tests are retired. Git history
and the existing `v2.0.0` release/tag preserve the final legacy-capable state;
the historical [v2.0.0 record](v2.0.0.md) describes its commands. Scripts that
need those interfaces must use that historical version. Supported current
commands are documented in the [README](../../README.md).

## Source and build architecture

Both flavours and both stock references use `sonicretro/s2disasm` REV01 at
exactly `380f37a731bfc720bb0371a35a593184a7ec5e43`, retained in
`config/dependencies.json`. There is no upstream dependency update.

`make bootstrap` uses ignored `build/source-modern/` as a read-only dependency.
Preparation clones committed input into disposable, isolated trees. Upstream's
Lua build and native tools assemble, compress, finalize the header checksum and
apply their existing power-of-two padding. No finished-ROM patch is applied.

| Role | Source policy | Output |
| --- | --- | --- |
| Retail stock REV01 | Untouched pinned upstream | `build/sonic2-stock-modern.md` |
| Production MD+ | Pristine retail policy plus Forge | `build/sonic2-mdplus.md` |
| Stock Bugfixed | Frozen curated policy, no Forge | `build/sonic2-stock-bugfixed.md` |
| Bugfixed MD+ | Frozen curated policy plus Forge | `build/sonic2-mdplus-bugfixed.md` |

Production uses `fixBugs=0`, prepared in `build/prepared-modern/`. Its public
commands, package name and strict Stage 5 identity remain stable.
`bootstrap-modern`, `prepare-modern` and `build-modern` remain Production
aliases. The relative `build/sonic2-modern-mdplus.md` compatibility symlink
still points only to `sonic2-mdplus.md`.

Bugfixed uses `build/prepared-bugfixed/` and `--bugfixed` selection for
preparation, ROM building, verification, packaging and full builds. Its Make
targets include `source-bugfixed`, `rom-bugfixed`, `package-bugfixed` and
`all-bugfixed`. It first reuses authoritative `bugfixed.apply_policy()`, verifies
all three post-policy source hashes, then applies the shared Forge adapter.
The adapter does not reconstruct or extend the curated policy.

Both stock references are independent development audits with no package
command. Stock Bugfixed has its own strict verifier and exclusion audits;
it is not verified through the MD+ Bugfixed profile.

## Frozen curated gameplay policy

The authoritative [Bugfixed policy](../BUGFIXED.md) enables ordinary upstream
main-game inline corrections under `fixBugs=1`, including code, objects,
rendering, collision, camera and mappings, with the documented exclusions.
Hash and contextual-anchor checks guard the three changed source files;
other tracked upstream inputs, including `build.lua`, remain unchanged.

Included upstream choices cover Oil Ocean background restoration, Spin Dash
camera history, runtime workarounds for malformed CPZ/DEZ door and OOZ spring
data, Tails rolling deceleration, CPZ boss collision, ARZ boss/AI-Tails
behaviour, multisprite/display priority and debug visibility/menu corrections.
These are the existing frozen policy, not additions during release preparation.

Three narrow downstream corrections remain part of that policy:

- **MCZ right drill:** correct the upstream boss drill-detachment facing-right
  operand from `sub5_x_pos(a0)` to `sub2_x_pos(a0)`. Compiled regressions execute
  both orientations.
- **ARZ Obj2B Rising Pillar:** retain explicit-height culling, display width
  `$1C` and display radius `$20`, but subtract eight only from the vertical
  collision half-height. Retail-equivalent jumping/walking collision is
  restored at all seven rising heights. MiSTer gameplay exposed this regression.
  The two-byte insertion is absorbed by existing local alignment; Forge
  placement, Z80 and Production remain unchanged.
- **ARZ Obj82 pillars:** retain explicit-height culling and display radius
  `$32`, but subtract two from `d2` before deriving `d3`, restoring retail
  jumping/walking collision `$30/$31`. Upstream compensated walking collision
  while leaving jumping collision at `$32`. Source and compiled analysis found
  this mismatch. The reordered 18-byte sequence is size-neutral; only its local
  branch label moves, with no downstream address movement.

The historical Obj2B-corrected stock `FDED` / `51263146...` and MD+ `6B57` /
`f80d983b...` identities remain evidence for that stage. Obj82 yields the current
stock `FDEC` and MD+ `6B56` identities below. The changelog and Bugfixed record
retain those transitions and their qualification distinctions.

### Exclusions and deferred polishing

`FixDriverBugs=0` and `FixMusicAndSFXDataBugs=0` remain enforced, including the
compressed-song setting in unchanged `build.lua`. Forge's own frozen handoff,
three-slot SFX-copy and Saxman-loader corrections are retained and audited.
Enabled main-game fixes can affect when native audio requests are issued;
they do not import upstream driver logic or music/SFX data fixes.

The complete alternate 2P sprite-table page-flip mechanism remains excluded:
`ForgeFix2PSpritePageFlip=0` gates all eleven related conditionals, including
the negative companion conditions. Its alternate tables would occupy the
Forge RAM reservation. Upstream Fixed Files are not copied.

Post-v3 polishing may separately evaluate the selected upstream fixes agreed for
that phase: the Spin Dash Release and Credits music/SFX data corrections,
EHZ2/ARZ2 Fixed Files and the WFZ conveyor correction, with CPZ/DEZ door data
and the OOZ2 launcher subtype requiring further research. The alternate 2P
sprite-table page-flip remains deliberately excluded; Sky Chase and Death Egg
music-data fixes are not part of the planned polishing phase. Z80 driver fixes
remain deferred to a later phase.
There are no new gameplay, audio, loop or level-data changes in this release pass.

## Forge ROM and RAM layout

Both layouts are independently audited against actual listings and ROM bytes.
Address spans below have exclusive ends.

| Field | Production | Bugfixed |
| --- | --- | --- |
| Meaningful stock sound-data end | `$0FFFEC` | `$107FEC` |
| Forge base | `$100000` | `$108000` |
| Forge backend end / handoff start | `$1002B6` | `$1082B6` |
| Handoff end / live-router start | `$1003A8` | `$1083A8` |
| Forge end | `$1006C0` | `$1086C0` |
| Saxman helper hook | `$0EC0DE` | `$0ED0DE` |
| Compressed Z80 start | `$0EC0E8` | `$0ED0E8` |
| DAC start | `$0ED100` | `$0F5100` |

The curated alignment cascade moves meaningful sound data past 1 MiB;
unchanged upstream padding produces a 2 MiB stock Bugfixed reference. Forge
occupies only `$108000-$1086BF` inside that existing padding. The gaps
`$107FEC-$107FFF` and `$1086C0-$1FFFFF` remain zero. Curated sound data stay
reference-identical. The independent baseline audit restores exact stock hooks
and Forge mutation spans to reconstruct the complete unmasked stock Bugfixed
SHA-256; no broad gameplay or trailing-data region is ignored.

Both variants preserve the `$FFF100-$FFF5FF` RAM hole. Forge allocations are
the counter at `$FFF100` (four bytes), duck state at `$FFF108`, and owner,
pending, handoff, paused and active bytes at `$FFF111-$FFF115`. `$FFF110` remains
deliberately unallocated. `Game_Mode` stays at `$FFF600`; alternate 2P tables
are absent. Early hooks remain fixed; moved curated pause hooks, the loader,
absolute handoff callback and bank switches are checked against their own
profile rather than inferred from Production.

## Z80 invariants

Complete decompression and actual loader execution are compared with the
assembled driver. Both Forge loaded images are 4,986 bytes; code ends at
`$137A`, with music beginning at `$1380` and six bytes of headroom preserved.

| Image | Compressed bytes | Loaded bytes | Loaded SHA-256 |
| --- | ---: | ---: | --- |
| Production MD+ | 4,009 | 4,986 | `9f997cc7217dda878297f7359f3314c7876aeb29e8705d63bd4b6db1513db24f` |
| Bugfixed MD+ | 4,011 | 4,986 | `f2883990453ba7deedc682b3970be0d2c73fea99a566a30d43362c2769ac7041` |

Exactly 34 loaded bytes differ between Production and Bugfixed, all derived
from actual relocated ROM addresses in eight complete bankswitch expansions:
four `SoundIndex` sites, `SndDAC_Start`, `Snd_Sega`, `MusicPoint1` and
`MusicPoint2`. Every remaining byte is identical, including Forge additions.
The independent stock audit also proves exactly 34 address-derived differences
between its 4,872-byte loaded drivers (3,940/3,942 compressed bytes).

The Bugfixed Forge payload ends at `$0EE093`, `$47` beyond the nominal
`Snd_Driver_End=$0EE04C`, but inside the audited growth region ending at
`$0F5100`. Padding after the payload is zero. Strict checks preserve these
actual and nominal boundaries without weakening the compressed/loaded audit.

The private stop request `F7` and ACK `A5`, music-only ownership handoff,
three-slot SFX-copy boundary, SFX progress under mailbox contention and final
compressed-byte loader correction retain the frozen Forge behaviour.

## MD+ protocol and transaction invariants

Each variant has sixteen fixed soundtrack routes and five control primitives:
exactly 21 adjacent open/write/close transactions, 42 control-address
signatures for `$0003F7FA`, 21 command-address signatures for `$0003F7FE`,
21 command writes, 21 opens and 21 closes. Every transaction closes the overlay
immediately. Initialization remains after Sonic's startup checksum at `$382`;
compiled tests prove no overlay write precedes checksum completion and a failed
checksum never opens it. Opening early would corrupt checksum reads and cause
the red-screen failure.

Native temporary music, pause/resume, fade/stop, 255-VInt extra-life ducking,
speed-shoes policy, ordinary SFX, VInt and reset retain their existing
semantics. MD+ speed variants remain disabled. Missing WAVs do not alter ROM
routing; the optional missing-WAV hardware test remains unrun.

**The exact current `6B56` / `d1668976...` Bugfixed MD+ ROM is hardware-qualified
on MiSTer FPGA, Mega Drive core `26.06.03`, after targeted Obj82/ARZ and relevant
MD+ lifecycle/audio tests.** The qualification preserves this evidence chain:

1. The earlier integrated `8101cf55...` ROM underwent broad full-game 1P testing

3. Obj2B was corrected; the exact `f80d983b...` build passed targeted ARZ,

   collision compensation; this was not a separately reported hardware

5. The size-neutral Obj82 correction restored both retail collision inputs;
   software audits established unchanged unrelated integration behaviour.
6. The exact current `d1668976...` ROM passed targeted Obj82/ARZ tests and

Current-hash results cover Act 1 Obj82 subtype `$10` and Act 2 subtype `$11`

## Packaging and upgrade behaviour

Production retains `dist/Sonic 2 - Addryu Mega-CD Remix MD+/`; Bugfixed uses
`dist/Sonic 2 - Addryu Mega-CD Remix MD+ (Bugfixed)/`. Each has matching ROM/CUE
basenames, the same sixteen `trackNN.wav` files and `SHA256SUMS.json` covering
the ROM, WAVs and CUE (19 files total, including that metadata). Both prepared
trees, ROMs and package directories coexist.
Reserved output paths prevent one flavour from overwriting the other;
Production's compatibility symlink never selects Bugfixed.

Packaging strictly verifies the selected ROM's own identity and reuses
`build/audio/` with the unchanged manifest, loop coordinates and conversion
policy. WAV checks retain 44.1 kHz signed 16-bit stereo PCM and 588-frame
sector alignment. Historical package evidence confirms unchanged WAVs/CUE
and coexistence for the current Bugfixed hash; local release-preparation
packaging checks reuse already prepared lawful audio without changing it.

After upgrading from v2.0.0, run `make rom` before `make package` and use
`make rom-bugfixed` / `make package-bugfixed` for Bugfixed. Current strict
packaging rejects stock references, prior legacy images and the other flavour.
No new soundtrack purchase, loop policy or audio conversion policy is introduced.
