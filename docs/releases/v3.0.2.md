# Sonic 2 MD+ Forge v3.0.2

Release date: 2026-10-04.

Version 3.0.2 freezes the CPZ/DEZ Obj2D door-data work merged through PR #47
on top of v3.0.1's selective audio and level-data corrections. Production
remains the default and byte-identical to its hardware-qualified Stage 5 image.
Bugfixed retains isolated outputs and its independently verified identity/layout.
Release preparation changes metadata and documentation only; it does not change
the merged ROM/gameplay implementation or extend the curated policy.

This release contains tooling, configuration and documentation only. It does
not distribute Sonic 2 ROMs, Sega game assets, upstream source/assets, Addryu
audio, converted soundtrack files, disc images or generated MiSTer packages.
Users supply their own lawfully obtained soundtrack files for local builds.

## Why a patch release

Semantic Versioning applies to Forge's tooling/public interface. Since v3.0.1,
no public command/API has been removed or incompatibly changed, and no new
public feature requires a minor-version bump. The already validated and
hardware-qualified door corrections therefore warrant a patch release.
`pyproject.toml` and runtime `__version__` in `tools/mdplus_builder/__init__.py`
are synchronised to `3.0.2`. Command names, flags, defaults, output names and
packaging behaviour remain unchanged. Production stays the default;
`--bugfixed` selects the isolated curated flavour.

The [v3.0.1 release record](v3.0.1.md) remains byte-for-byte unchanged. Its
identities and evidence are historical baselines, not redefined as v3.0.2.
The breaking legacy-interface retirement remains part of [v3.0.0](v3.0.0.md).

## Source and build architecture

All four maintained ROMs use `sonicretro/s2disasm` REV01 at immutable commit
`380f37a731bfc720bb0371a35a593184a7ec5e43` in `config/dependencies.json`.
The dependency pin is unchanged. Ignored `build/source-modern/` remains a
read-only input; preparation clones committed input into disposable trees.
Upstream Lua/native tools assemble and finalize the ROM; no finished-ROM patch
is applied.

| Role | Source policy | Output |
| --- | --- | --- |
| Stock Production | Untouched pinned REV01 | `build/sonic2-stock-modern.md` |
| Production MD+ | Pristine retail policy plus Forge | `build/sonic2-mdplus.md` |
| Stock Bugfixed | Curated game/data policy, no Forge | `build/sonic2-stock-bugfixed.md` |
| Bugfixed MD+ | Curated game/data policy plus Forge | `build/sonic2-mdplus-bugfixed.md` |

Bugfixed reuses authoritative `bugfixed.apply_policy()`, validates all eleven
post-policy source/object hashes, then applies the shared Forge adapter. The
adapter does not reconstruct or extend the policy. Stock Bugfixed retains its
independent strict identity, verifier and exclusion audit. Neither stock
reference has a package command.

Production preparation, names and compatibility aliases remain unchanged.
`build/sonic2-modern-mdplus.md` remains a relative symlink to
`sonic2-mdplus.md`, selecting only Production. Both prepared trees, ROMs and
package directories coexist; reserved output paths preserve isolation.

- WFZ1's diagonal conveyor subtype correction.

Global `FixMusicAndSFXDataBugs=0` and `FixDriverBugs=0` remain enforced, including
compressed-song builds. Sky Chase/Death Egg audio-data changes and upstream Z80

2P sprite mechanism excluded.

### CPZ/DEZ door-data policy

Adopt all nine pinned Fixed Files Obj2D subtype `$00 -> $02` replacements as
one atomic decision with retirement of both Bugfixed runtime `$03` stores:

| Layout | Replacements |
| --- | ---: |
| CPZ1 | 2 |
| CPZ2 | 4 |
| DEZ1 | 3 |

Pristine/reference/target hashes and complete edit shapes are checked before
policy outputs are written. Positions, flags, IDs, ordering and file lengths
remain unchanged; only the selected door subtypes change. The three layouts
join the prior eight unchanged policy outputs. All unselected Fixed Files,
including OOZ2 push springs, remain excluded.

The old Obj2D workaround forced `$03` in both zone-art initialization branches,
regardless of placement subtype. Pinned references actually select `$02`;
retaining the stores would override the selected data. Both six-byte runtime
instructions and their conditional wrappers/obsolete hack comments are removed
together. Generic subtype-to-mapping-frame initialization remains. Compiled
tests establish that frames 2 and 3 have identical mappings and compare complete
initialization, collision arguments, trigger limits and movement at all nine
placements. Other-zone Obj2D users retain generic subtypes. Production retains
the pristine source; `fixBugs=0` already omits both conditional instructions.

## Binary/layout relocation and reconstruction

Removal of the two runtime stores changes layout through existing alignment:

| Region | Movement from v3.0.1 |
| --- | --- |
| Between removed stores | -6 bytes |
| Later code/maps | -12 bytes |
| Player assets | -32 bytes |
| Rings | -256 bytes |
| Objects | -512 bytes |
| Loader / sound / Z80 boundaries | Unchanged |

Both Bugfixed ROMs remain 2 MiB. Alignment absorbs the movement before
`SoundDriverLoad=$0ED000`. Every byte from `$0ED000` to ROM end is identical to
v3.0.1 in each variant. Bugfixed Forge remains `$108000-$1086BF`, exclusive end
`$1086C0`, after sound end `$107FEC`; Production Forge remains at `$100000`.
RAM allocations and the `$FFF100-$FFF5FF` hole remain unchanged.

Each Bugfixed ROM differs at 808,214 byte positions from its v3.0.1 counterpart.
These positions are accounted for by removals, relocation/pointers, alignment,
nine subtype bytes and checksum; that count does not represent 808,214 gameplay
changes. Independent inverse reconstruction copies every surviving byte through
seven disjoint movement intervals, checks zero alignment padding, restores the
two instructions and retail subtypes, and reverses 2,425 address fixups:
2,362 absolute operands, 60 word branches, two short branches and one Obj2D
index word. No broad unexplained masks or replacement blobs are accepted.
Complete symbol movement is independently checked for stock and MD+ layouts.

The inverse returns the exact historical v3.0.1 identities:

```text
Stock Bugfixed (53DB):
9ff0b7b577de237cf2fe9e13415a943b7d30e228a12b96b851793c95ece7184f
Bugfixed MD+ (C145):
f33a1946a609b8045bb56ffce2aba05196190965fed6ddf5f8eb3b80c52a0c52
```

The earlier level/audio audits first reverse the door phase, then check their
unchanged historical baselines. Independent integration checks still cover
loader/hooks, compressed/loaded drivers, eight Z80 bank-switch expansions and
complete curated-baseline reconstruction. All 21 adjacent open/write/close MD+
transactions, 42 control signatures and 21 command signatures remain unchanged.
Overlay activation stays after Sonic's startup checksum; a failed checksum
never opens it. ROM checksum, signatures, PCM and sector checks are preserved.

## Targeted MiSTer hardware qualification

The exact released Bugfixed MD+ `0951` / `e9f56f0e...` identity above was tested
on MiSTer FPGA, Mega Drive core `26.06.03`. This is retained qualification of
the exact merged identity, not a new hardware session during release preparation.

| Target | Coverage and result |
| --- | --- |
| CPZ1 | 2/2 affected doors: PASS |
| CPZ2 | 4/4 affected doors, including route-dependent placements: PASS |
| DEZ | 3/3 affected doors: PASS |

CPZ1 closed collision, open traversal and opening/closing were correct, with no
clipping/sticking; act progression/transition was normal. CPZ2 passed the same
door checks, with no door-related progression fault. DEZ collision/traversal
was normal, with no clipping or visual/object corruption; Mecha Sonic and Death
Egg Robot progression succeeded and the ending transition triggered.

Pause/unpause, MD+ -> temporary native music -> MD+ restoration, soft reset and
Level Select all passed. No sprite/object corruption or targeted hardware
regression was observed.

Brief CPZ2 slowdown while invincibility was active remains a non-blocking
observation. Additional object load is a plausible explanation, but it is not
proven stock-normal, was not reproduced as a door fault, and no evidence
currently links it to this identity. It is not a resolved bug claim or a new
unrelated bug claim.

**This exact v3.0.2 Bugfixed MD+ identity is hardware-qualified for the targeted
door-data/runtime-workaround scope and listed regression sanity.** This is not
a new full-game playthrough, comprehensive 2P soak or retest of every historical
Bugfixed correction. It does not qualify OOZ2 or resolve issue #26. See the
[complete door hardware record](../BUGFIXED.md#targeted-door-data-mister-hardware-qualification).

Production retains its passed [Stage 5 hardware gate](../MODERN_STAGE5.md#mister-hardware-results)

`dist/Sonic 2 - Addryu Mega-CD Remix MD+ (Bugfixed)/`. Use `make rom` /

preparation: code/inputs are unchanged and the request excludes altering existing
audio/package assets. The v3.0.1 record retains its fresh local two-package,

historical packaging evidence, not fresh v3.0.2 package verification. Synthetic

soundtrack input is needed for those tests.
